# MLIR-RL Progress Reporting Runbook (Unified & Accelerated)

Use this skill to fetch, synchronize, and report the current status of all training jobs, evaluation batches, and storage quotas in under 2 seconds.

---

## 🛠️ Step 1. Run Unified Fast Report
Run the fast report script to get training progress, active Slurm jobs, evaluation status, and Lustre quota in a single execution (runs concurrently using background threads):
```bash
python scripts/utils/fast_report.py -d ops_and_blocks
```
*Note: Redirect output to a temporary file and read it to prevent truncation of wide tables.*
*Distributed (V5.1) runs show their dask worker fleet (count + nodes) in the Slurm jobs table and a Workers column in the training table; workers are attributed only to the distributed run whose driver is active.*
*The report covers ONLY experiments registered in `experiments.json` (repo root — accessible from any context). Before launching a new experiment, register it there (name, config, results_dir, mode, seed, state, description). Each report call auto-updates the `state` field (pending → running → done/failed/stopped). Set `"archived": true` on an experiment to permanently hide it from all report tables (used for concluded experiments, e.g. `v5_single_node`).*

---

## 📊 Step 2. Present the Output Report
Directly print the output generated by the script, which is formatted as Markdown tables representing:
1. **Active Slurm Jobs Table**
2. **Training Progress Table**
3. **Evaluation Progress Table**
4. **Lustre Storage Quota Table**

**Mandatory output shape:** every report MUST contain all 4 sections, each rendered as a Markdown table, printed verbatim from the script output. NEVER replace any section — especially **Training Progress** — with a prose summary or bullet list. Tables are printed even when a section has no rows (header + empty body). Keep any commentary to ONE short line AFTER the 4 tables (e.g. notable changes: new failures, run finished, quota risk). **This applies to ANY follow-up question about train/eval state too (e.g. "what's evaluated / what's not / what will the jobs cover") — always answer in Markdown table(s), never as bullet lists or prose.**
